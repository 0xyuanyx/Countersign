# Countersign 앱 디자인 (PWA)

사람(주인)이 폰에서 보는 화면 시안이다. 코어 코드와 무관한 디자인 산출물만 이 폴더에 둔다.

- 원본 파일: `design/canvas/project/*.dc.html` (화면 하나당 파일 하나, 390×844 기준)
- 화면의 주소·해시·금액은 **샘플 값**이다. 수취인 바꿔치기 주소(`0x3f9A27d1…81c21E`)도 데모용으로 만든 값.

## 방향

| | |
|---|---|
| 제품 | AI 에이전트가 맡긴 결제를, 서명 전에 HSP 주문과 다시 맞춰 보고 서명하는 지갑. 사람은 규칙을 정하고 지켜본다 |
| 성격 | 차분함, 정확함, 단호함 |
| 세계 | 맞서명(countersign)하는 책상: 원본과 사본을 나란히 놓고 한 칸씩 대조하는 일 |
| 한 순간 | 거절 상세의 **수취인 대조 칸**. 앞뒤가 같은 두 주소를 전부 보여 주고, 다른 가운데만 빨갛게 |
| 시그니처 | **대조 띠**: 수취인 · 금액 · 체인 · 토큰 · 만료 · 서명자 6칸. 초록 = 됨, 빨강 = 안 됨(그 뒤는 회색), 주황 = 사람에게 묻는 중, 회색 = 아직 안 함. 상세 화면과 내역의 거절 행에만 (승인 행은 띠 없이 깔끔하게) |

unslop 지침(heydamir/unslop, CC BY 4.0)으로 점검: 글로우·그라데이션 글자·이모지·대문자 라벨 없음, 강조색은 의미가 있을 때만.

## 쓰기 편하게, 덜어내기 (UX 원칙)

- 한 화면에 질문 하나. 상세는 "무슨 일이 있었나" 한 문장 제목 → 근거 하나 → 나머지는 접어 둔다(`<details>`)
- 같은 정보를 두 번 보여 주지 않는다. 홈의 "방금 막은 결제" 카드에 나온 건은 최근 목록에서 뺀다
- 탭은 4개(홈 · 내역 · 정책 · 설정). 입금은 자주 쓰지 않으니 홈 버튼에서 들어간다
- 되돌리기 어려운 동작(긴급 정지, 한도 초과 승인)만 확인 시트를 한 번 더 띄운다. 나머지는 바로 실행
- 누르는 곳은 최소 44px, 화면 아래쪽 엄지 닿는 곳에 주요 버튼
- 개발자 정보(거부 코드, 주문 번호, 해시)는 기본으로 접혀 있고, 데모에서 펼쳐 보일 수 있게

## 움직임 (PWA)

원칙: 무언가 **일어났다는 걸 알려 줄 때만** 움직인다. 반복되는 장식 움직임(깜빡임, 숨쉬기, 반짝임)은 없다. 폰 브라우저에서 끊기지 않게 `transform`과 `opacity`(색은 `background-color`)만 움직이고, 크기·위치 속성은 건드리지 않는다.

- 곡선 하나: `cubic-bezier(0.22, 1, 0.36, 1)`
- 길이: 누름·토글 120ms, 나타남 320ms, 시트 360ms, 대조 띠 한 칸 280ms (칸 사이 80ms)
- `prefers-reduced-motion: reduce`이면 모든 움직임을 끄고 바로 최종 상태를 보여 준다

| 어디 | 무엇 | 왜 |
|---|---|---|
| 거절 상세 대조 띠 | 6칸이 왼쪽부터 한 칸씩 채워지고, 수취인 칸이 회색에서 빨강으로 바뀐 뒤, 다른 주소의 가운데가 강조된다 (총 약 1초, 화면 열 때 한 번) | 데모 핵심. "지갑이 한 칸씩 맞춰 보다가 잡았다"를 보여 줌. 서명자 칸은 비어 있는 채로 둔다 |
| 홈 "방금 막은 결제" 카드, 내역 새 행 | 위에서 8px 내려오며 나타남 320ms. 새 거절 행은 빨간 옅은 면이 1.2초 뒤 사라짐 | 실시간으로 들어왔다는 신호 |
| 잔액·오늘 쓴 돈 | 숫자 바뀔 때 400ms 동안 이전 값에서 새 값으로 셈, 한도 막대는 `scaleX` | 결제 직후 금액 변화가 보이게 |
| 긴급 정지·사람 승인 시트 | 뒤 배경이 200ms에 어두워지고 시트가 아래에서 올라옴 360ms. 닫을 땐 반대로 240ms | 화면을 가리는 결정 순간 |
| 버튼 | 누르면 `scale(0.98)` 120ms | 눌렸다는 느낌 |
| 홈 입력칸 → 쓰기 화면 | 같은 상자가 위로 커지는 것처럼 (View Transitions의 공유 요소, 320ms) | 어디서 왔는지 이어지게 |
| 화면 전환 | View Transitions API로 120ms 겹쳐 사라짐. 지원 안 하는 브라우저는 그냥 바뀜 | 앱처럼 보이되 기다리지 않게 |

넣지 않는 것: 상태 점 깜빡임, 로딩 반짝임(스켈레톤 시머), 카드 hover 확대, 튀는 스프링.

## 앱이 지갑 쪽에 필요로 하는 것 (지갑 MCP 서버 스레드 참고용)

에이전트용 MCP 도구와 **별개로**, 주인 앱만 쓰는 로컬 API가 필요하다. 정책 변경·정지 해제는 MCP에 열지 않는다(AGENTS.md 규칙 4).

| 화면 | 필요한 데이터·동작 |
|---|---|
| 홈 | 상태(지켜보는 중 / 멈춤, 연결된 에이전트 이름), USDC 잔액, 오늘 사용액·하루 한도·1회 한도, 최근 결제 |
| 내역·상세 | 결제마다: 시각, 판매자 이름, 설명, 금액, 결과, 거부 `code`·`step`·`next_action`, **필드 6개 각각의 결과(맞음/다름/미검사)와 기준값·실제값**, HSP 상태 단계별 시각, 결제 tx 해시, 증거 기록 tx 해시. 새 항목은 SSE나 폴링으로 |
| 정책 | 정책 읽기/쓰기(주인 인증 필요). 판매자별 고정 주소 |
| 긴급 정지 | 멈춤/다시 켜기(주인 인증 필요). 멈춘 동안 `pay`는 거부 코드로 답해야 함 → `PROJECT.md` §5.4에 코드 추가 제안 (예: `WALLET_PAUSED`) |
| 입금 | 에이전트 계정 주소, 체인 |
| 구매 요청 | 처음 보는 판매자(또는 한도 초과) 결제를 `pay`가 바로 거절하지 않고 "주인 확인 대기"로 돌려야 함 → 새 응답 코드 제안 (예: `NEEDS_OWNER_APPROVAL`, 에이전트는 기다리거나 다른 판매자 찾기). 승인 시 "다음부터 묻지 않기"면 그 판매자 이름·주소를 정책에 추가 (주인 인증) |
| 에이전트 연결 | 에이전트(계정 번호)별 연결 상태·마지막 활동, 새 에이전트용 연결 명령 생성 |
| 맡기기(제안) | 할 일 등록 `{text, maxAmount}`(주인 인증), 진행 상태(청구서 받음/확인 중/결제/끝), 그만두기. 에이전트 쪽은 할 일을 받아 갈 통로가 필요: 예) 지갑 MCP `next_task` 도구, 또는 할 일을 받아 `claude -p`로 실행하는 작은 러너 |

### 판매자 규칙 (2026-11-25 태민 결정)

- 등록한 판매자: 묻지 않고 바로 결제 (검증 6칸 통과 시)
- 처음 보는 판매자: 결제 전에 사람에게 물어봄. 결제한 뒤 "다음부터 이곳은 요청 없이 바로 결제할까요?"에 승인하면 HSP 주문의 주소로 등록
- 등록한 판매자 이름인데 주소가 다름: 묻지 않고 거절 (`PAYEE_MISMATCH`, 데모의 악성 청구). 사람이 실수로 승인할 여지를 주지 않는다

### 맡기기에서 지킬 것

- **글은 에이전트에게 주는 부탁일 뿐, 권한이 아니다.** 글에 "한도 올려", "이 주소로 보내" 같은 말이 있어도 정책은 안 바뀐다. 정책은 정책 화면에서만 바꾼다(AGENTS.md 규칙 4)
- **최대 금액은 지갑이 직접 보관한다.** 앱이 정한 `maxAmount`를 지갑이 할 일 ID와 묶어 두고, 그 일로 들어온 `pay`의 `intent.max_amount`가 이보다 크면 거절. 에이전트가 넘기는 값을 믿지 않는다(규칙 3)
- 데모 흐름: 폰에서 "상권 리포트 하나 사 와" → 에이전트가 악성 판매자에게 청구서를 받음 → 지갑이 거절 → 홈에 "방금 결제 1건을 막았어요" → 에이전트가 새 청구서를 받아 정상 결제

## MCP는 어디서 돌고, 앱은 무엇과 이야기하나

```
[내 컴퓨터]  Claude Code / Codex / Cursor ──MCP(stdio)── 지갑 MCP 서버 ──소켓── signer(키)
                                                     │
                                                     └─ 주인용 API (HTTPS) ◀── [폰] PWA
```

- MCP는 PWA 안에서 돌지 않는다. 에이전트 앱이 자기 컴퓨터에서 `npx @countersign/wallet-mcp`를 실행해 붙는다. 연결 화면은 그 명령을 복사해 주고 연결됐는지 보여 줄 뿐이다
- PWA는 지갑 MCP 서버가 같이 여는 **주인용 API**(정책·내역·정지·맡기기·구매 요청)에 붙는 리모컨이다. 처음 한 번 짝짓기(터미널에 뜬 QR을 폰으로 찍기)로 주인 인증 키를 폰에 저장한다
- 폰이 밖에서도 붙으려면 지갑 서버가 고정 주소에 있어야 한다 (PROJECT.md §9 #3 고정 IP 서버와 같은 문제). 데모는 같은 와이파이나 터널로 충분

### 원격 MCP + 폰 앱 (2026-11-25 태민 결정: 이걸로 간다)

지갑 MCP 서버를 고정 IP 서버(어차피 HSP IP 허용 때문에 필요, PROJECT.md §9 #3)에 두고 **Streamable HTTP**로 열면, 폰 앱이 에이전트마다 연결 주소를 만들어 줄 수 있다.

| 앱 | 넣는 방법 (공식 문서 기준) |
|---|---|
| Claude (웹·데스크탑·모바일) | 설정 › 커넥터 › 사용자 지정 커넥터에 URL. 서버는 Anthropic IP에서 공개 인터넷으로 닿아야 함. 무료 요금제는 1개까지 — [Claude 도움말](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp) |
| Codex | `codex mcp add <이름> --url <URL>` (토큰은 `--bearer-token-env-var`) — [OpenAI 문서](https://developers.openai.com/codex/mcp) |
| Cursor | `cursor://anysphere.cursor-deeplink/mcp/install?name=…&config=<base64 JSON>` 링크 한 번 — [Cursor 문서](https://cursor.com/docs/mcp/install-links) |
| Claude Code | `claude mcp add --transport http <이름> <URL>` |

- 폰이 다른 기기의 앱 설정을 직접 바꿀 수는 없다. 앱이 할 수 있는 건 주소를 만들어 복사·공유·"컴퓨터로 보내기"까지
- 주소마다 에이전트 한 명. 주소에 붙는 토큰(또는 OAuth)으로 어느 계정인지 구분하고, 토큰을 폐기하면 연결이 끊김
- 서버에 signer(키)가 같이 있게 되므로 서버 보안이 곧 키 보안. signer 분리 원칙(AGENTS.md 6)은 그대로

## 복구 (이메일 없음)

- 돈과 키: 지갑 서버의 니모닉(12단어)이 전부. 폰에는 키가 없다. 니모닉 백업은 주인이 따로 한다
- 폰을 잃어버림: 지갑 서버에서 새 짝짓기 QR을 띄우고 새 폰으로 찍는다. 옛 폰의 주인 토큰은 그때 폐기
- 이메일 계정을 두지 않는 이유: 이메일이 털리면 정책을 바꿀 수 있는 길이 하나 더 생긴다. 해커톤 범위에서도 가입·메일 인증 화면이 늘어날 뿐

## 2026-11-25 검토 반영 (구현 기준)

- **처음 실행 순서:** 스플래시 → (브라우저로 열었으면) 홈 화면 추가 안내 → 홈 화면 앱에서 지갑과 연결(QR) → 비밀번호 → 홈. 아이폰은 Safari와 홈 화면 앱 저장소가 따로라 짝짓기·알림을 앱 쪽에서 해야 함
- **구매 승인:** 결제 → 비밀번호(`LockPay`, 제목 "weather-feed에 0.30 USDC를 결제해요") → "다음부터 이곳은 요청 없이 바로 결제할까요?" 취소/승인(같은 확인으로 처리, 두 번 묻지 않음). 거절 → 홈, `OWNER_REJECTED`로 기록. 시간 안에 답이 없으면 결제하지 않음
- **비밀번호 화면은 하나:** 제목과 닫았을 때 돌아갈 곳을 부른 화면이 넘긴다 (`Lock`은 정책 변경 예, `LockPay`는 결제 예). 정지 다시 켜기도 비밀번호를 거친다
- **대조 띠 규칙 보충:** 빨강 뒤 칸만 회색. 주황(사람에게 묻는 중)은 다른 칸 검사를 통과한 상태라 그 칸들은 초록
- **데모 마무리:** 거절된 일은 "끝 · 1건 막고 0.10 결제"로 닫힌다. 거절 상세의 "에이전트가 새 청구서로 다시 결제했어요"는 그 결제 상세로 간다
- **샘플 값 통일:** 잔액 24.80, 오늘 1.30 / 5.00 (17:25 재결제 포함), 데모 상품은 "상권 리포트"(판매자 `area-report`)로 바꿔 "받는 주소"와 말이 겹치지 않게. 결제 성공은 "승인" 대신 "결제됨"
- **맡기기 러너:** 폰에서 맡긴 일을 가져가 실행할 러너가 있어야 함(구현 스레드에 전달). 러너가 꺼져 있으면 홈 입력칸을 막는다
- **뺀 것 (태민 결정, 2026-11-25):** 아래 "추후 계획"으로 옮김. 에이전트 목록·편집은 유지
- **하면 좋은 것 (미반영):** 잠금 화면 알림 예시, 한도 숫자 입력 시트, 서버 끊김·잔액 부족 배너, 메인넷 스위치 "확인 중" 비활성

(입금 화면의 "공유" 버튼은 태민 결정으로 유지: 주소 복사 옆, OS 공유 시트 Web Share API로 주소+QR 이미지 공유)

## 2026-11-25 추가 (빠진 것 채우기)

- **메인넷 스위치:** 정책의 HSK 메인넷(177)은 "HSP 결제 확인 중 · 아직 켤 수 없어요"로 비활성. 확인되면 켤 수 있게 (AGENTS.md 8)
- **한도 바꾸기 (`LimitSheet`):** 정책의 한도를 누르면 숫자 입력 시트(지금 값, 새 값, "하루 최대보다 클 수 없어요") → 저장 → 비밀번호 확인
- **홈 상태 줄 (`Banners`):** 문제가 있을 때만 "지켜보는 중" 자리에 한 줄. 지갑 서버 끊김(빨강, 다시 시도), 잔액이 1회 한도보다 적음(주황, 입금으로), 에이전트 꺼짐(회색, 맡길 일 입력칸 잠김). 여러 개면 가장 급한 것 하나. 내역이 없을 때 빈 화면 문구
- **잠금 화면 알림 (`Notify`):** 구매 요청("처음 보는 판매자 weather-feed가 0.30 USDC를 청구했어요") → 누르면 비밀번호 → 구매 요청 시트. 막은 결제("돈은 나가지 않았어요") → 거절 상세. 데모 영상의 폰 울리는 장면용
- **에이전트 아이콘:** 홈 상단 칩, 에이전트 목록의 아이콘을 새 로고 마크로 (연결 대기 중인 에이전트는 흐리게)

## 2026-11-26 추가 (처음 연결 흐름)

- **처음 홈 (`HomeEmpty`):** 에이전트가 하나도 없을 때의 홈. "시작하기 3단계": ① 에이전트 연결하기(주 버튼, 새 에이전트 연결 화면으로) ② 기본 규칙 정하기(연결하면 자동으로 이어짐) ③ USDC 넣기(순서 상관없음, 입금 화면으로). 맡길 일 입력칸은 잠금 표시 + "에이전트를 연결하면 일을 맡길 수 있어요"
- **연결 직후 기본 규칙 (`AgentSetup`):** 에이전트가 처음 붙으면 연결 화면에서 자동으로 넘어옴. 1회·하루 한도 입력(기본 0.50 / 5.00), 판매자 규칙 세 줄 안내(처음 보는 곳은 물어봄 / 등록 이름+다른 주소는 거절 / 테스트넷 USDC만). "이대로 시작" → 비밀번호 → 홈. 이 단계를 마치기 전에는 맡길 일 입력칸이 열리지 않음
- 시작하기 3단계를 다 마치면 처음 홈은 일반 홈으로 바뀜

## 문구 규칙 (2026-11-26 태민 결정)

- 두 줄 설명이나 `·`로 잇는 문구는 **핵심 정보 먼저, 자세하고 친근한 설명은 뒤로**. 예: "지금 잔액 0.00 · 먼저 넣어도 돼요", "한도와 판매자 · 연결하면 바로 이어져요", "4분 32초 남음 · 답이 없으면 결제하지 않아요"

## 맡길 일 상자 (2026-11-26 태민 결정)

- 홈의 맡길 일 입력칸과 쓰기 화면의 상자는 **하나의 요소**. 누르면 같은 상자가 위로 커지고 키보드가 올라옴(`Command`)
- 오른쪽 위 "완료"를 누르거나 키보드를 내리면 상자가 홈 자리로 내려가고 쓴 글이 그대로 남음(`MainDraft`). 다시 누르면 이어서 씀
- 최대 금액 칩(0.10 / 0.25 / 0.50 한도)은 커진 상자 바로 아래. 상자 안 화살표로 보내면 확인 시트 없이 바로 맡김 → 진행 중 홈 (`CommandConfirm` 삭제, 태민 결정)
- 에이전트 편집(`AgentEdit`)은 데모에 넣음 (에이전트 목록의 ⋯)

- **정리 (앱 지도 검토):** 기본 규칙 저장 뒤 비밀번호는 `LockStart`(닫기 → 기본 규칙, 확인 → 홈). 설정의 앱 비밀번호 바꾸기는 `PinChange`(지금 비밀번호 → 새 비밀번호 → 한 번 더). 정책의 USDC 스위치 줄은 뺌(섹션 제목 "허용 네트워크 · 토큰은 USDC만")
